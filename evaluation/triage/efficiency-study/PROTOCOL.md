## Fixed question and arms

Does Serene adoption reduce observable SQL-construction investigation cost or improve
correct dangerous-site arrival within a common budget? Compare two new small billing/
warehouse application tasks × R conventional Raw SQL and S uniform Serene conversion
with available audit. Normal file listing, literal/regex/case-insensitive search,
range reads and dependency-context retrieval are available equally. R is not forced
to grep or review every site; S is not forced to run audit. No semantic bug or Rules/
layout score. Identical filenames, functions, SQL/value behavior, schema and context
within each pair; all static two-argument query literals convert by the same AST
rule without gold input. Bypasses remain dangerous. The author never saw the earlier
scored answers and authored new source, not the repeated calibration generator.

Tasks are illustrative application repositories with 23 true driver sites each,
not random production samples. They have similar shapes and compact source; disclose
possible ceilings and correlated task difficulty. Static methods and real workflow
code replace repeated calibration dummies. Preparation errors/corrections are retained
in evaluator notes. Gold N is 3 conceptual execution paths per task: an imported
finite chooser needing proof, nonlocal dangerous predicate provenance, and a forwarding
execution wrapper needing caller follow-through. The wrapper's caller maps to its
single actual helpers.send site; do not double count. Immediate finite choices are
resolved, not N. D is 1 per task, independently validated with SQLite witnesses.

## Budget and observable cost definition

Freeze B=10 unique dependency-expanded or explicitly context-retrieved driver sites,
600 elapsed seconds from first action, 262144 returned JSON-payload UTF-8 bytes and
80 requests. Same limits in both arms, whichever binds first. Checkpoints B=1,3,5,10.
Retain these pilot-scale caps after unrelated transport calibration; do not optimize
them to scored answers. Output request: at most 1200 final words, exec output budget
30000 tokens. This requested output bound is not an enforced model token ceiling.

`investigate` returns actual source context and counts indexed execution sites in
that function, unlike the old counter-only begin. Independently, all read/search
responses update source-line exposure. A site is automatically expanded once its
owner body and a referenced local helper/caller span have both been exposed, even
without an investigate request. Imports are narrowed to names actually used in
that function; reverse caller spans apply to SQL-forwarding parameters. No gold is
read by the indexer. B rejects new content that would exceed the site limit. A full
file containing many independent helpers can expose several sites at once; charge
that event to each linked site but count its bytes/read once. Repeats cost actions/
bytes/time but not additional unique sites. Failed/capped requests are logged.

This is an observable **context-expansion proxy**, not a measurement of private
mental effort. It can overcount exposure without attention and miss unobservable
reasoning. Report it alongside actual read/search counts and bytes, never label a
self-reported number as measured cognitive depth. Reading all caller code is counted
in bytes/actions even if classified as brief screening. Statements can be diagnosed
without an explicit investigate action; correct finds still count. No instruction
requires gratuitous deep reads. Ordinary-library docs/audit consumption is charged
in S. Setup/conversion cost is excluded from review cost and disclosed.

Use file-backed locked controller state; counters cannot reset across ordinary
client invocations. Source access must use this interface only. It is instruction-
scoped, not physical isolation; shared files remain technically readable. Root does
not claim detection of every unlogged access. Invalid mediation/trace failures are
retained; no replacing failed answers. The controller log stores exact responses,
chronology, delivered ranges, cumulative bytes/sites/time and failed requests.

## Outcomes and frozen interpretation

Co-primary: (1) context-expanded sites and objective reads/searches/bytes at first
correct D finding, with elapsed time disclosed as wall time including orchestration;
(2) correct D discovery within checkpoints and final B, plus D recall. Record N
referrals/inspection recall separately, normalizing wrapper callers to actual sites.
A dangerous finding needs a source location and correct untrusted-syntax mechanism;
classification labels alone earn no hit. False findings, false safe dismissals,
unnecessary expanded resolved sites and review-required resolution costs remain
separate. Audit-ordinary is not ground truth. No composite score with business bugs.

Preserve every trajectory through declared finish/cap. No-hit trajectories are
censored, never zero-cost or dropped. Initial screening and audit bytes are included.
Per-task paired results are the unit; no significance calculation on four runs.
A practical pilot signal requires D/N coverage not reduced, no additional confirmed
false findings, and either >=20% lower context-expansion count at discovery or
higher D arrival within B. If primary counts tie, report objective byte/read changes
as secondary rather than selecting a favorable winner. Time/tokens alone cannot
establish a robust win here. Two tasks provide feasibility evidence, not broad
product utility. Equal recall without lower measured effort is not evidence of
compression; equal recall with lower effort must not be dismissed as 'no difference'.
