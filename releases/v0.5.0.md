# Serene 0.5.0

Serene 0.5.0 adds bounded PostgreSQL TEMP materialization while preserving Serene's fixed-SQL review boundary.

### PostgreSQL TEMP materialization

- Add `materializeTemp(body, 'name')` for a fixed `CREATE TEMPORARY TABLE ... ON COMMIT DROP AS` wrapper around an existing unbound Serene `Sql`.
- The body keeps Serene provenance and is bound only after composition; plain strings, extracted `sourceText`, shape-compatible objects and `BoundSql` do not establish provenance.
- Ordinary source classification requires a literal TEMP name. Runtime names are still syntactically bounded to a single quoted ASCII identifier.
- Statement terminators outside recognized PostgreSQL quotes/comments are rejected so the body cannot escape the single CTAS statement.
- Existing `ORDER BY` state is preserved across TEMP materialization.

### Review behavior

- TEMP materialization remains visible through the independent `SQL_CREATE_TEMP` review signal.
- The `DROP` in the generated `ON COMMIT DROP` lifecycle clause is not treated as a destructive `SQL_DROP`; real DROP occurrences and body review signals remain visible.
- Audit provenance and signals propagate through binding, native QueryConfig recognition, execution findings, `--actionable-only`, and source/diff filtering.

### Verification

- Real PostgreSQL 18 CI verifies bound values, same-connection TEMP consumption, and cleanup after commit, rollback, and failure followed by rollback.
- Packed runtime, audit/filter exports, and TypeScript declarations are verified; the runtime remains dependency-free.
