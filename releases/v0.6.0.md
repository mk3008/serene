# Serene 0.6.0

Serene 0.6.0 expands the independent SQL-content review axis while keeping construction provenance and strict gates unchanged.

### Elevated review priority

- Add optional review-signal priority and use `priority: "elevated"` for review-heavy SQL paths.
- Add `SQL_PERSISTENT_DDL` for bounded `CREATE` / `ALTER` shapes covering tables, views, functions, procedures and triggers on recognized Serene SQL paths.
- Keep runtime TEMP creation advisory rather than treating it as persistent DDL.

### Procedural SQL and delegated execution

- Add elevated `SQL_PROCEDURAL_BODY` for PostgreSQL `DO` blocks and recognized routine/trigger definitions across PostgreSQL, SQL Server and MySQL/MariaDB forms.
- Add elevated `SQL_ROUTINE_CALL` for statement-entry `CALL`, `EXEC` and `EXECUTE`, without claiming whether execution is a fixed routine or dynamic SQL.
- Do not flag ordinary dollar-quoted text, generic `BEGIN` / `END`, `EXECUTE AS`, or `SELECT`-style function calls solely from these forms.
- Keep procedural bodies opaque: Serene identifies review-heavy containers and execution entry points but does not parse PL/pgSQL, T-SQL or MySQL stored-program control flow.

### Review behavior

- Construction remains independently classified as `ordinary`, `review-required` or `violation`.
- Elevated content signals keep recognized SQL visible for review but do not cause `--strict` to fail by themselves.
- Signals continue to propagate through recognized binding, native QueryConfig usage, execution findings, `--actionable-only`, source filtering and diff filtering.
- Standalone migrations and arbitrary SQL strings remain outside Serene's recognized-source scope.

### Verification

- The procedural review additions bring the suite to 297 tests, with lint and TypeScript checks passing.
- Packed-package verification covers the new elevated signals.
- Existing PostgreSQL 18 transaction/binding regressions remain green.
