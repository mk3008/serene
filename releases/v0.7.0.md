# Serene 0.7.0

Serene 0.7.0 adds an explicit external-SQL binding boundary and refines PostgreSQL temporary-DDL review classification, while preserving the distinction between construction provenance and content review.

### Explicit external SQL

- Add `externalSql(text)` and `bindExternal(...)` for SQL text that intentionally has no Serene source provenance.
- External SQL can reuse Serene's parameter validation, named-marker lowering, quote/comment/dollar-quote shielding, unused-parameter checks and driver-facing bound shape.
- `ExternalSql` and `BoundExternalSql` remain identity-backed and separate from source-backed `Sql` / `BoundSql`.
- Runtime `review()` returns `review-required` / `EXTERNAL_SQL` before and after binding.
- Source audit keeps external paths visible, including through `--actionable-only`, source filtering and diff filtering; `--strict` still fails on external provenance.
- External SQL cannot be promoted into ordinary Serene provenance through casts, copied shapes, approval flags, `bind`, `orderBy` or `materializeTemp`.
- No new connection or execution abstraction is introduced; native-driver usage remains unchanged.

### PostgreSQL temporary DDL refinement

- Add advisory `SQL_TEMP_DDL` for bounded statement-entry `ALTER TABLE pg_temp.<fixed identifier>` forms.
- Only the matching explicit `pg_temp` ALTER occurrence is removed from elevated `SQL_PERSISTENT_DDL`; other persistent definitions in the same SQL remain elevated.
- Unqualified targets, arbitrary schemas, internal `pg_temp_N` names and unsupported modifier forms keep the conservative elevated fallback.
- The rule relies only on explicit source text and does not infer lifetime from prior statements, `search_path`, catalog state or runtime inspection.

### Review behavior

- Construction levels remain `ordinary`, `review-required` and `violation` with their existing meanings.
- Binding success never means semantic approval, authorization, correctness or safety.
- Existing persistent-DDL, procedural-body and routine-call review signals continue to work independently from provenance.
- Standalone migrations and arbitrary SQL outside recognized Serene source paths remain outside source-audit coverage.

### Verification

- The full suite now contains 329 tests with lint and TypeScript checks passing.
- Packed-package verification covers the new external SQL exports, types and runtime behavior.
- PostgreSQL integration regressions remain green.
